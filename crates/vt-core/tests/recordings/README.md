# Recorded sessions

Each recording here is a real program, run in a pseudo-terminal and driven by a script, as asciicast v2: `vim`, `htop`, `tmux`, `less`, `fzf` and `vttest`. The tests replay them through the VT core, and look at the screen at their markers and at their end.

- **A script** (`*.script`) sets the program up, with `size`, `copy` (a file, of `files/` or of the build's `target/` as vttest's, into the program's directory), `allow window-ops` (the terminal lets the program change its size, which the recording's header notes for the replays), `env` and `run`, then drives it, with `wait "text"` (until the screen shows it), `quiet` (until the output stops for a while), `sleep`, `send "keys"` (once the program takes them), `mark name` and `exit`; `wait`, `quiet`, `send` and `exit` take a limit in milliseconds, ten seconds by default, and a mark's name is its own, neither `exit` nor with a `/`. The scripts say what each recording shows.
- **Snapshots** (`snapshots/`): `tools/replay/tests/goldens.rs` replays each recording and keeps the screen, its text, the attributes of its cells and the cursor, as `bolt-replay --attributes` prints them, with the terminal's replies since the point before, at each marker and at the end, `exit`, as `insta` snapshots. A change of the terminal that changes a screen fails them: `cargo insta review` (from `cargo install cargo-insta`) shows each change, or `INSTA_UPDATE=always cargo test -p bolt-replay --test goldens` writes them all, for `git diff` to show.
- **Recording again**: `just record` builds vttest from its pinned commit into `target/vttest`, then runs every script with `bolt-record`, which needs the other five programs installed, and writes each recording next to its script. A recording changes with the programs' versions, which the tests' snapshots then show.
- **What the programs see**: the session's terminal, which answers their queries, `TERM=xterm-256color`, and no environment but a few variables, in a directory of their own that is also their home, so that no user's configuration plays a part. `htop` shows itself alone, without the user's column, from `files/htoprc`, and `tmux` a status line without the host or the time, from `files/tmux.conf`. `vttest` sets mode 40 and switches to 132 columns, as xterm lets it, so its script allows the window's operations.
- **Nothing private**: the recorder refuses to write a recording that shows the user's name or full name, the host's or the computer's name, the user's home, the temporary directory and the folders above it, when they are the user's own, as on macOS, the long name of one, or the program's own home, whose path is the machine's. It looks on the screen after each read and, once the program is done, in:
  - the bytes that the program wrote, as they are, without their control characters but for the line breaks and the tabs, and with their percent-encoding undone;
  - the payloads of the OSC, DCS and APC strings, which the parser reads, and the text of the SOS and PM strings, which it drops, found where its escape state finds them: each as it is and without its control characters, and each of those with its percent-encoding undone;
  - what each run of base64 in the output stands for, of 4 characters or more, in the alphabet for URLs too, from wherever its groups start, with the chunks of kitty's graphics and of OSC 1337's files joined, which covers OSC 52's clipboard and the files;
  - the bytes typed into it, all of them together;
  - the text that the VT core's parser prints from the output, without its escape sequences;
  - the titles and the working directory;
  - every line of both screens, the scrollback's too, its soft-wrapped rows joined, as the screen shows them: an empty cell is a space, so that text that a tab or a move of the cursor separates is not joined;
  - the screen of a terminal on which the output replays, before each control and escape sequence, which are what take text away: a name that one read draws and erases shows there.

  A name that the recorder cannot look up, as when `hostname` fails, is said on its standard error and not checked. So are names shorter than 3 characters, which would match too much. The machine's cores, load, memory and uptime, in `htop`'s header, are not private.
